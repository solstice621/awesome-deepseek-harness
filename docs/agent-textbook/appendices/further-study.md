# 进阶方向与范围边界

[教材目录](../README.md)

本书覆盖以语言模型为决策组件的软件 Agent 工程主线，三个案例都面向编码及通用工具任务。它们能帮助理解观察、状态、执行和反馈，却不足以代表所有 Agent 研究。进阶学习应在同一概念框架上增加新的环境约束，而不是把功能名称无限加入架构图。

## 研究问题怎样接到工程机制

| 方向 | 本书已有基础 | 进一步需要学习的问题 |
|---|---|---|
| 学习式策略与强化学习 | 第 1、5、24 章的策略、反馈与评测 | 奖励设计、训练数据、信用分配、探索和策略更新；本书不推导训练算法 |
| 搜索与规划算法 | 第 5 章的分解与验证 | 搜索空间、代价函数、分支剪枝、可验证世界模型；自然语言计划不等于执行了最优搜索 |
| 机器人与具身 Agent | 第 7、13、18 章的环境、时序与约束 | 感知噪声、控制频率、实时限制、物理安全和硬件闭环 |
| 浏览器与多模态 Agent | 第 2、7、8 章的消息、观察与动作协议 | 图像定位、页面变化、动作后再观察、可访问性与可重复环境 |
| 业务流程 Agent | 第 14、17、25 章的幂等、授权与运营 | 跨服务事务、补偿、角色职责、规则变化和审计保留 |
| 大规模检索与知识维护 | 第 9—11 章 | 语义索引、增量更新、权限传播、删除传播、领域验证集 |
| 多 Agent 研究 | 第 21—24 章 | 通信协议、协作收益的因果归因、共享环境冲突、重复评测 |

这些是课程扩展方向，没有据此声称三个项目已经实现对应研究系统。

## 概念文献与阅读问题

以下原始论文页面已核对标题与摘要，用作进一步精读入口。这里仅介绍研究问题，不复述其全部实验，也不把历史论文成绩当作三个项目的当前能力。

**ReAct** 将推理轨迹与任务动作交错组织，让动作取得外部观察并影响后续推理。阅读时结合第 4、5 章，区分论文中的显式文本轨迹、模型不可见的内部计算，以及运行时真正执行的动作。本书不要求暴露模型内部推理才能实现可审计系统。[ReAct 原始论文](https://arxiv.org/abs/2210.03629)

**Reflexion** 研究用语言反馈和情景记忆影响后续尝试，而不是更新模型权重。结合第 10、24 章追问：反馈来自何处，保存了什么，错误反馈会不会累积，以及如何用对照实验确认改进。[Reflexion 原始论文](https://arxiv.org/abs/2303.11366)

**Retrieval-Augmented Generation** 研究把参数化模型与可检索的非参数记忆结合。原论文的具体实现使用稠密索引和神经检索器；本书第 10 章采用更宽的工程流程含义，把代码搜索后生成也作为检索增强工作流，而不声称它复现了该论文模型。[RAG 原始论文](https://arxiv.org/abs/2005.11401)

**SWE-bench** 把真实仓库问题与代码修改作为评测对象，强调仓库环境下的软件工程任务。结合第 24 章思考为什么“单函数答案通过”与“仓库问题解决”有不同的环境、验证和成本边界。本教材没有运行该基准，也不提供排行榜比较。[SWE-bench 原始论文](https://arxiv.org/abs/2310.06770)

OpenAI 的官方 SDK 运行说明提供了模型、工具、交接与停止点的另一种公开解释，可与本书的概念循环对照。这是在线 SDK 文档，不是本书固定 Codex 源码版本的行为规范。[Running agents](https://developers.openai.com/api/docs/guides/agents/running-agents)

## 从教程实验走向真实评测

模拟决策器能使故障重现，却消除了模型选择的不确定性。换成真实模型之后，应保留同一工具契约和独立验证器，再固定任务集、模型版本与设置、权限、环境和预算。先看是否正确调用工具，再看任务结果；先解释失败种类，再计算总成功率。

例如比较“先规划”和“直接行动”，至少控制工具集合、总预算和验证器。若规划方案用了更多模型调用，它的提升不能简单归因于规划文字。类似地，多 Agent 获得更好结果时，应检查收益是否只是来自更多尝试、更多 token 或更宽权限。

一个值得研究的开放问题，应能写出可证伪的假设。例如“保存带来源与版本的项目记忆，能减少重复搜索且不增加过期规则误用”，就同时规定收益和风险；“让 Agent 更聪明”则没有给出可检验对象。课程最后的成果应是能够继续验证的设计和证据，而不是不加限定的能力宣言。
